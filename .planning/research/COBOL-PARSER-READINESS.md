# COBOL Parser/Grammar Readiness: Handoff from tree-sitter-cobol-upgrade

**Date:** 2026-09-30
**Unblocks:** Phase 2 (Thin Deterministic Native Tracer), Phase 3 (COBOL and Mainframe Breadth), Phase 5 (Explicit Unresolved Evidence). STATE.md lists "COBOL parser/grammar readiness" as the Phase 2 blocker; this document is the readiness evidence and the integration guide.
**Producer:** the `tree-sitter-cobol-upgrade` fork (private repo `MuiGoku123432/tree-sitter-cobol-upgrade`, branch `gsd/v0.26.0-estate-parse-recovery`, milestone v0.26.0 "Estate Parse Recovery", audited and accepted by the developer 2026-09-30).

> **This repository is public.** Never paste estate source, member or program names, private root paths, or run IDs into anything tracked here. Use invented COBOL in fixtures only.

## TL;DR

- The grammar and a deterministic preprocessor are ready to consume. They are delivered as two local Go modules through `go.work` (neither is published).
- The recommended integration is to call the preprocessor's public API per COBOL file and map its versioned handoff (`cobol-handoff-v1`, frozen) into Gortex's native `ExtractionResult`. Do not walk raw tree-sitter output of unpreprocessed source.
- Measured on the private estate (aggregate only): about 81% of development programs and 80% of the sealed holdout grade **green**, up from about 19% at the baseline. The rest are **amber** or **red**, and each red program comes with explicit gaps instead of silently wrong structure.
- Gortex today extracts COBOL with regexes (`internal/parser/languages/cobol.go`) and does not use this grammar. That regex extractor is what Phase 2 replaces or wraps.

## 2. The API to call

```go
import (
    "github.com/MuiGoku123432/tree-sitter-cobol-upgrade/preprocessor"
    "github.com/MuiGoku123432/tree-sitter-cobol-upgrade/preprocessor/transform"
)

// Once: repoRoot is the fork checkout. NewAnalyzer attests that the compiled
// grammar matches forest-shim/cobol in that checkout and fails otherwise.
an, err := preprocessor.NewAnalyzer(repoRoot, catalog)

// Per file: original is the raw member bytes; locator is a stable relative path.
id, err := preprocessor.NewSourceID(locator)
h, err := an.Analyze(ctx, id, original) // handoff.Handoff, already validated
```

- **Catalog:** `transform.NewCatalog(map[string]transform.CatalogElement)` is an injected INCLUDE/COPY name graph with no filesystem access. The fork's own disk loader (`loadIncludeCatalog`) is unexported. Start with `transform.NewCatalog(nil)`: `-INC` rewrites are symbolic, so generated bytes do not depend on catalog content, but the catalog's ID does feed the configuration identity. Asking the fork for an exported loader is a reasonable follow-up.
- `handoff.Validate`, `handoff.Encode` and `handoff.Decode` exist if the handoff is persisted or moved between processes. `handoff.CheckParser(h, tool)` detects a handoff produced by a different grammar build.

## 3. The handoff, mapped to Gortex concepts

`handoff.Handoff` (schema `cobol-handoff-v1`) holds one document:

| Field | Meaning | Gortex use |
|---|---|---|
| `SourceID`, `OriginalContentID` | Stable source and content identity | Canonical identity and change detection |
| `Generated` | Preprocessed bytes that were actually parsed | Content for names: `Generated[span.Start:span.End]` |
| `Map` | Validated, reversible generated-to-original source map | Every persisted range must be **original** coordinates |
| `Facts.Observations[]` | Every named, missing or error node: `Kind`, generated `Span`, `Original` projection, `Parent` index, `Affected` flag | Nodes and containment edges in `ExtractionResult`. The structure is already there, so no second parse is needed. `Affected=true` means the node overlaps an error cascade and should be treated as degraded. |
| `Gaps[]` | Unresolved evidence: named unparsed tails, ERROR/MISSING, timeout/no-tree, lost or unmapped captures. Each has a stable `ID`, `Kind`, `Reason`, `Severity`, `Scope`, optional generated/original ranges, `NodeKind`, `ExpectedFamily`, `Container`, and `AbsenceReason` when a value is unavailable | Phase 5 `PARSE_UNRESOLVED` findings. A missing copybook or target (`Target` / `AbsenceReason`) maps to `EXTERNAL_UNRESOLVED`. |
| `Assessment` | Grade `green` / `amber` / `red` plus reasons, under a policy version | Per-document trust. Green means use as-is; amber or red means keep the facts but mark them degraded |
| `ToolID`, `Tool`, `ParseConfigurationID`, `Ledger.ConfigurationID` | Grammar build, parse budget and transform configuration identity | Provenance. Re-index when any of them changes. |

Graph-relevant node kinds come from the grammar's queries (`queries/idms.scm`, `cics.scm`, `sql.scm` in the fork) and include program/division/paragraph/section headers, data items, COPY (including `COPY IDMS [kind] name`), CALL, PERFORM, IDMS DML navigation/update/session statements, EXEC CICS, and EXEC SQL.

## 4. Boundary rules (fork decision D10; keep them)

- The fork emits **deterministic facts and gaps only**. Gortex owns native graph conversion, repository scoping, SQLite persistence, AI-inferred claims, review, and any Neo4j projection. Do not ask the producer for graph mutations or confidence values.
- Never invent coordinates. If a gap has no range, it carries an `AbsenceReason`. Surface that value as-is.
- The consumer contract fixture is `preprocessor/handoff/testdata/consumer-v1.golden.json` in the fork. **Do not pin** `ledger.configuration_id` or `gaps[].id` in Gortex tests: they change on every producer transform-config bump (a known fork issue). Assert structure, kinds, ranges and reasons instead.

## 5. Suggested sequencing against this roadmap

1. **Phase 2 (tracer):** fix `go.work` (section 1), then register a COBOL extractor that calls `Analyze` on one invented fixture and emits one named program node and its source-file edge through `ExtractionResult`, repository prefixing, the indexer lifecycle and SQLite `AddBatch`. Keep the regex extractor as the fallback until parity.
2. **Phase 3 (breadth):** derive paragraphs, sections, PERFORM/GO TO, CALL (static and dynamic), COPY, data items, IDMS, CICS and SQL from `Observations`. Resolve names from `Generated`, and store original coordinates.
3. **Phase 4 (lifecycle):** key incremental reuse on `OriginalContentID` + `ToolID` + configuration IDs.
4. **Phase 5 (unresolved evidence):** map `Gaps` to `PARSE_UNRESOLVED`, and missing targets to `EXTERNAL_UNRESOLVED`.

## 6. Known limitations on the producer side

- **Memory:** a few pathological programs make tree-sitter's C-side error recovery spike (tens of GB peak footprint; Go heap stays near 160 MB; not a leak). Parse one file at a time, or with low concurrency, on 16 GB hosts. The fork's 4-worker determinism check (`run-verify`) is OOM-killed on such hosts, and the investigation is deferred.
- **Wall clock:** `Analyze` enforces a per-document parse budget and a 2-minute ceiling. A document that exceeds either becomes a document-level gap or an infrastructure error, never a partial silent result.
- **Modules not published:** local `go.work` only. CI for Gortex cannot use the shim until the fork publishes tagged modules or the grammar is upstreamed.
- **Not yet covered by the grammar:** some long-tail forms remain gaps by design (for example certain IDMS DML tails, REMARKS paragraphs, EXEC SQL residuals, and programs starting at PROGRAM-ID without an ID division header). They surface as explicit gaps.
