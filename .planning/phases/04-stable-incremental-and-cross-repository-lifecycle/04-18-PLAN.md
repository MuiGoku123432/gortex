<objective>
Close the root-cause half of VERIFICATION `gaps[0]` (CR-01, nested tracked checkout). A per-repository walk or watcher must stop at any other tracked repository's root that lies inside its own. Each path then has exactly one owner, the nested repository, and the outer repository no longer mints `alpha/nested/...` nodes. Those nodes are what let the ownership audit report Clean while one file had two owners (D-14, D-15, SEC-08). Without them, a projection or query scoped to alpha no longer carries beta's symbols (D-16, SEC-01).

Purpose: The verifier preferred fixing the root cause ("MultiIndexer hands each Indexer the sibling roots"). Plan 04-17 makes every source surface agree in every index state. This plan removes the duplicate population that made the surfaces able to disagree in the first place.
Output: one predicate on the Indexer, one registered-root check on the MultiIndexer, one seed at Indexer construction, one watcher check, and the nested-root tests.
</objective>

## Gap closed

VERIFICATION `gaps[0]`, `missing` item 1 first option ("Prune other tracked roots in the per-repository walk (MultiIndexer hands each Indexer the sibling roots)") and `missing` item 3 ("assert the nested fixture's PrefixDiagnostics has no alpha/nested/... nodes"). Plan 04-17 covers the second option of item 1 and item 2. Both run in wave 10 and share no file.

Design (decided here, justified):
- **Where:** `Indexer.shouldExclude` already decides symlink confinement for every walk, `shouldPruneDir`, the warm-reconcile census, and explicit-path incremental sites. `Watcher.isExcluded` is the live-path twin that does not route through it. The tracked-root check goes in exactly those two places, the same split symlink confinement uses, so no admission path is missed.
- **Which roots:** (a) the global config's tracked roots, copied once when the MultiIndexer builds the Indexer. During a parallel warmup (`indexMultiRepo` workers, the daemon's warmup pool) a sibling is not yet in `mi.repos` when this repository walks. The daemon warms exactly `Global().Repos`. (b) The roots registered in `mi.repos`, read live. This covers repositories tracked later or without a config entry, and keeps the watcher correct after a later track.
- **Not per file:** `ReposSnapshot` copies under a package mutex, so it runs once per Indexer and never per file or per event.
- **Only strictly nested roots count:** a root that equals the walk root or contains it never excludes anything, so beta's own walk is unaffected by alpha.
- **Fork hygiene (project constraint):** this edits upstream internals, which the constraint asks to minimize. The admission predicate lives on the unexported `Indexer` and is consulted inside upstream's walk and watcher code, so an additive package cannot reach it. The footprint is kept to one field, one Indexer method, one MultiIndexer method, one constructor block, and two one-line calls.

## Flagged assumptions

- The project-scoped `IndexScoped` case (an active project whose repositories are defined only under `projects:`, not in the top-level `repos:` list) is not seeded from the config. If such a nested pair is indexed in one batch, the outer repository may still index the nested files once. Plan 04-17's gate keeps every source surface consistent in that state, and the outer repository's next `IndexRepo` or warm reconcile drops the duplicates, because by then the nested root is registered. The daemon and the test fixtures use top-level `repos:`.
- If a test in `internal/indexer`, `internal/mcp`, or `cmd/gortex` relied on an outer repository indexing a tracked root nested inside it (for example a linked worktree tracked inside its main checkout), that expectation is the double ownership this plan removes. Update such a test only when its assertion is exactly that duplicate. Record each one in the SUMMARY. Any other failure is a regression to fix in the predicate.

## Deferred (not gaps; out of scope here)

- Evicting the outer repository's duplicates at the moment a nested repository is tracked. Today they go on the outer repository's next reindex or warm reconcile. 04-17's gate keeps source surfaces consistent in the window. Doing it at track time means taking the outer repository's mutation lane from inside the nested track, which needs a lane-ordering design of its own.
- Untracking a nested repository leaves its files excluded from the outer repository until the outer Indexer is rebuilt (`IndexRepo` or a daemon restart), because the config seed is captured at construction. This fails closed: the files are not indexed, rather than misattributed.
- WR-04 rename_symbol message policy and the concurrency warnings (REVIEW-FIX WR-01; re-review WR-01, WR-02) are human decisions in VERIFICATION `human_verification`.
