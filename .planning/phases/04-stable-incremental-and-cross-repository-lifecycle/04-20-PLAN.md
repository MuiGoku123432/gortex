<objective>
Close the seed half of VERIFICATION `gaps[1]` (status partial; review CR-01 and WR-01). Plan 04-18 seeded nested-root pruning from a construction-time copy of the global config's top-level `repos:`. That copy is the wrong set:
- It misses `projects:` entries, so beta is indexed twice (CR-01 under-prune).
- It includes entries the batch does not index, so files vanish (CR-01 over-prune).
- It never refreshes, so after untrack alpha keeps excluding beta's files and incremental differs from clean (WR-01).

This plan replaces the copy with the set actually being indexed. A batch declares the repositories it is about to index: `indexMultiRepo` declares its resolved list, and the daemon warmup declares the list it feeds its pool. Pruning reads those declared roots together with the live registered roots (`mi.repos`), under the RLock 04-18 already takes. Nothing is copied per Indexer, so nothing can go stale.

Purpose: SC-4/ID-09 requires incremental to equal clean for identical final inputs, and SEC-08 requires one owner per file. Both depend on the walk excluding exactly the roots that are, or are about to be, tracked.
Output: one MultiIndexer field and one exported method, one declaration in indexMultiRepo, one in the daemon warmup, the simplified predicate, and four tests.
</objective>

## Gap closed

VERIFICATION `gaps[1]` `missing` item 1: "Seed nested-root pruning from the list indexMultiRepo or TrackRepoCtx is actually indexing, and use live mi.repos after publication (drop the per-Indexer config copy ...)". This plan also covers the projects:-map and inactive-entry tests in `missing` item 3. Plan 04-21 closes `missing` item 2 (reconcile the enclosing repository on track and untrack) and the remaining untrack and track-later tests.

Design (decided here, justified):
- **Declared, not copied.** A batch knows exactly which repositories it is about to index. `DeclarePendingRoots` puts their roots in one MultiIndexer map that `nestedTrackedRootContains` already reads under its RLock. The returned release removes them. After release, pruning follows `mi.repos` alone. Untrack and config reload therefore take effect immediately, with no refresh hook.
- **Reference counted.** Two `indexMultiRepo` batches with disjoint prefixes may run at once (both hold only `batchMutationGate.RLock`). A daemon declaration and a concurrent batch may share a root. A count prevents one release from removing another batch's root.
- **The daemon passes its own list.** The warmup tracks `repos` with a parallel pool, so a sibling is not registered when another repository walks. Declaring that same slice keeps the warmup exact. It does not rely on the config happening to match, which was the CR-01 failure mode. This touches one upstream file, `cmd/gortex/daemon_state.go`, with one call. The fork-hygiene constraint asks for minimal upstream edits; one line in the warmup cannot be reached by an additive package.
- **Lock order unchanged.** DeclarePendingRoots and release take `mi.mu.Lock` only for map updates and never walk, wait, or call out while holding it. The per-file check keeps 04-18's audited RLock. 04-18-SUMMARY "Lock-order audit" lists every caller; none holds `mi.mu`.
