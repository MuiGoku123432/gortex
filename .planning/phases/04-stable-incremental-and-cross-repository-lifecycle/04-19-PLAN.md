## Gap closed

VERIFICATION `gaps[0]`: "every tool that returns source bytes refuses a request with no resolved scope, and every source surface admits the same bytes for one allow-set". Each `missing` item maps to a task:
1. "Before the artifact lane runs, refuse an unbound multi-repo request ... as search_text does" → Task 1.
2. "Pass the lane's matches through filterTextMatchesByResolvedScope ... before taking snippets" → Task 2.
3. "Add explore (artifact-intent task plus a yaml fixture) to TestSourceScope_UnboundMultiRepoRefused and to both TestSourceScope_NestedCheckoutRefused states" → Tasks 1 and 2.

The orchestrator also asked for the inventory to be complete, so this class of gap cannot recur. Task 3 makes it structural and records the audit.

Design (decided here, justified):
- **Refuse rather than drop snippets.** A dropped snippet still lets a content hit raise a file's score, which tells the caller the text exists. Refusing before the lane, from the task text alone, mirrors search_text and find_declaration. It also satisfies the existing inventory assertion (`IsError`).
- **Refuse only when the lane will run text probes** (`artifactIntent.active` with probes). Path-only artifact intents and ordinary code tasks emit graph metadata, and D-13 keeps metadata on the all-repositories default for unbound sessions. Their source reads already fail closed at resolveNodePath and resolveFilePath.
- **Reuse `filterTextMatchesByResolvedScope`.** It is the same gate search_text and the search_symbols content fallback use. No new helper, and the lane's signature is unchanged. The ResolvedScope literal is built inline from the lane's QueryOptions.
