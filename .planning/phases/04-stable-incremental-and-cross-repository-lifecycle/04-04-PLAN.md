<objective>
Make the generic cross-repository fallback deterministic and fail closed (D-12, SEC-03). Today `resolveFunctionCall` step 2 and three loops in `resolveMethodCall` bind the first eligible candidate, and candidate order comes from iterating a Go map of reachable repositories, so a same-named symbol in two reachable repositories binds nondeterministically. Replace the first match with one private helper that binds only when eligible candidates sit in one repository and otherwise records an `ambiguous` reason with the candidate IDs.

Purpose: SEC-03 forbids same-name cross-repository binding without deterministic evidence; this is the accepted minimal edit to upstream code (D-12, fork hygiene).
Output: one helper, four call-site edits, Meta-only stamp persistence, and tests.
</objective>

## Flagged assumptions

- D-12 names only `resolveFunctionCall`, but its intent is "for all languages"; `resolveMethodCall` has the identical first-match pattern in three loops and gets the same edit (research Open Question 5, adopted).
- Generic-language incremental equivalence is out of the ID-09 corpus (COBOL only, adopted research default): an already-bound generic cross-repository edge is not re-checked when a new candidate appears later; the ambiguity stamp is decided per pass. Readers must consult `resolution_unresolved_reason` only when `To` is still unresolved, because a later same-repository bind by the master resolver does not clear it (Pitfall 8).
- Synthetic candidates with an empty RepoPrefix keep their current precedence, so this change alters behavior only where today's result depended on map order.
