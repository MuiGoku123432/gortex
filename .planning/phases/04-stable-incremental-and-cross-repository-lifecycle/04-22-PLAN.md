<objective>
Close the rest of the source-surface audit that 04-19 runs. The orchestrator asked to "consider whether any OTHER tool returns source bytes without a gate". The audit at planning time found three filesystem walks that apply the source gate only to their root:
- move_symbol's module walk and inline_symbol's module walk (D-20 writes).
- generate_skill's directory walk (D-13 copies).

Each walk then descends into any nested tracked root or symlink under that root without checking who owns each entry. In the nested topology an alpha-scoped move or inline can rewrite beta's Go files. An alpha-scoped generate_skill can copy beta's files into a skill bundle under alpha.

The fix is one call per walk, using the existing gate: `requirePathSourceScope(ctx, <root's repository>, entry)`. The plan also folds in review WR-05, which is trivially adjacent: find_declaration's regex branch caps at `limit` before the scope filter, so a scoped caller can get a false "no use sites matched". The fix mirrors the literal branch.

Purpose: SC-5/SEC-01 says every source surface admits the same bytes for one allow-set. 04-19's structural inventory lists these three walks, with the gate added here as their gate, and this plan makes that listing true.
Output: three gate calls, one grep-call change, one nested Go-module fixture, and four tests.
</objective>

## Gap closed

This closes the remainder of VERIFICATION `gaps[0]`'s class ("every source surface admits the same bytes for one allow-set"; 04-17 prohibition "MUST NOT admit a source path on any source surface by its lexical repository prefix alone") for the three walk surfaces found by the 04-19 audit. It also closes review WR-05, which the orchestrator listed as fold-in-if-adjacent: it is one call and one break in a function 04-19's inventory already names.

Design (decided here, justified):
- **Skip, do not refuse.** The edge loop in both handlers already skips an out-of-scope caller silently (`continue` on a resolveNodePath error). The walk guard matches that behavior inside the same function. Whether a scoped refactor should refuse when out-of-scope references exist is the rename_symbol message policy (WR-04/IN-06), a pending human decision. This plan does not decide it.
- **Per-entry gate with the root's lexical repository.** move and inline use `node.RepoPrefix`, the repository resolveNodePath gated. generate_skill uses the repository that owns the gated directory, computed once before the walk. A directory entry that the gate refuses is pruned with SkipDir, and a refused file is skipped (generate_skill counts it in `skipped`). The gate also resolves symlinked files, which the walks follow on read and write.
- **No new helper.** Three call sites use one existing function with one line each. Nothing is shared or extracted.
- **WR-05 keeps the scan cost.** GrepRegexpForRepos already caps each repository at `limit` inside GrepRegexp. The only change is removing the global cap that runs before the filter.
