<objective>
Make procedure-only copybooks first-class (user decision: fix now). Today a member the producer wraps with its procedure header yields only its file node, so its paragraphs, PERFORMs, and CALLs are invisible to impact queries. With the copybook root from Plan 03-15, `cobolProcedure`, `cobolStatements`, and `cobolFlow` run on the wrapper's procedure division and emit the member's sections, paragraphs, statements, and PERFORM/THRU/GO TO edges, owned by the copybook file node at the member's own coordinates. No wrapper program or division node is emitted (03-13 invariant). CALL and COPY edges already route through `w.id` (03-15), so they come out of the same walk.

Purpose: CALL, PERFORM, and COPY usage inside procedure copybooks reaches `get_callers` and `get_call_chain`, and labels the member does not define stay honest unresolved targets.
Output: the root mode in the procedure, statement, and flow walkers; the `label_not_in_copybook` reason; procedure-copybook unit tests; and a real-path test through SQLite and MCP.
</objective>

## Decision closed

VERIFICATION "Human Verification 1" (procedure-fragment copybooks emit no structure and no absence reason): the user chose to make them first-class now. Review WR-05's second bullet is the same finding. No producer change is needed: probing the pinned producer on invented members showed the procedure-header handoff already carries everything the walkers read. `program_definition` (the wrapper, synthetic `program_name`) has a direct `procedure_division` child, and the member's `section_header`, `paragraph_header`, and statement observations are its direct children, with exact original projections at the member's rows (row 0 is the member's first line). Statements before the first header are also direct children of that division.

ID choice (costly, D-07/D-10 extension): copybook procedure symbols start with the copybook root `@proc`, mirroring a program's `<prog>/@proc/<PARA>`, so a copybook paragraph is `<path>::@proc/<PARA>` and a statement before any header is `<path>::@proc/@<kind>`. `@` cannot start a COBOL word (A3), so these never collide with copybook data-item IDs (`<path>::<01 name>/…`).
