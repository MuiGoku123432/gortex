## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted EXEC CICS and IDMS operands to resource IDs | Resource names from repository files become shared node IDs across files. |
| Shared resource nodes to the store | One node is written by many files (first sighting per document, last writer in SQLite). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-25 | Tampering | resource IDs | high | mitigate | Keys pass through `cobolNameNorm` and `cobolIDSegment`; qualifiers come only from source or are the explicit `_unqualified` marker. |
| T-03-26 | Tampering | false binding of data-named operands | high | mitigate | Data-name operands go to per-program dynamic targets with reason `dynamic` and are never bound (prohibition, CICS link_dynamic and transid tests). |
| T-03-27 | Repudiation | shared node ownership | medium | accept | Pitfall 7: a shared node's FilePath is its last writer, as for go_sql tables; each relationship edge keeps its own full provenance, and ownership is Phase 4 (ID-04). |
</threat_model>
