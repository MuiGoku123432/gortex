<objective>
Close VERIFICATION gap 1 (status failed, not overridable): a separately compiled caller must never bind to a nested COBOL program. The extractor stamps `cobol_nested` on every program node from the same END PROGRAM containment walk that builds its ID, and `resolveCobolReferences` offers a nested program only to callers in its own file. A cross-file CALL whose only match is nested then stays `missing`.

Purpose: the phase goal forbids false deterministic resolution, and COBOL scoping makes a contained program uncallable from outside its container.
Output: the `nested` field and `cobol_nested` stamp, the resolver filter, resolver and extractor unit tests, and a real-path test on the persisted two-repository graph.

## Gap closed

VERIFICATION `gaps[0]`: "a literal CALL is bound only to a program a separately compiled caller can actually reach" (review WR-02). Both `missing` items are planned here: the candidate rule (Task 1) and the resolver test for a cross-file CALL to the only nested INNER (Task 1, `nested_cross_file_missing`).

Choice (orchestrator asked to pick): an explicit `cobol_nested` stamp at extraction, not a QualName `/` check in the resolver. Reasons: the stamp costs one struct field and one Meta line, it keeps the resolver free of ID-shape parsing, and a QualName check would be wrong today because program symbols are the verbatim `program_name` bytes (review IN-03), so a top-level literal `PROGRAM-ID. "A/B".` already has a `/` in its symbol. Task 2 pins that case.
