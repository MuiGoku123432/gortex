## Flagged assumptions

- Discretion (RESEARCH A5): the table records opens (`'' -> active` or `closed -> active`) as well as closes and supersedes. This is a superset of D-06 and is what lets 05-09 diff against history instead of reading the prior active set before every eviction path.
- Discretion (schema): a per-repository `seq` (MAX + 1 inside the write transaction) orders rows; no wall-clock timestamp is stored, so history carries no volatile value. The class, kind, container, and start byte columns exist so the next diff can pair a gone finding without its node.
- Discretion (migration): in-place additive (the v21 precedent), not `storeNeedsRebuild`; existing v22 stores gain an empty table on open (D-07: history starts empty).
- The in-memory `*graph.Graph` does not implement the history capabilities (adding Graph fields would be an invasive upstream edit); 05-09's pass probes the capability and is a no-op on in-memory stores.
- Scale (checker warning, revision 1): the ledger reads only the latest row per finding (`LatestFindingTransitions`, one indexed `GROUP BY finding_id` query), never the whole append-only log, so a pass costs O(findings) rather than O(history). The first pass after v23 still writes one open row per active finding (per-token SQL tails, D-18, can reach 10^5 rows in a large repository) inside one write transaction, chunked by the parameter bound; this is kept atomic so `seq` stays gap-free, and 05-11 measures it (`BenchmarkRecordFindingLedger_LargeRepo`, recorded in its SUMMARY). No compaction is added: history is a non-canonical, purge-on-untrack log (D-07).
