## Flagged assumptions

- Exclusion choice (D-23): the reach topology writer is the exclusion that the incremental raw executors (`incrementalReindexRepoRawMode`, `incrementalEvictRepoRaw`), the warm snapshot closure, untrack, and the standalone watcher already hold from file commit through their own reconcile and ledger, so a ledger that holds it can never read inside those lanes' commit-to-reconcile window; `cobolReconcileMu` additionally excludes reconciles that run outside any writer section (master ResolveAll during daemon warmup and deferred catch-up). No new lock is introduced.
- Cold-track gap (corrected premise; review of iteration 1): the cold track does NOT hold the writer from commit through reconcile. `trackRepoSourceCtx`'s closure commits under the writer and releases it on return; TrackRepoCtx then runs `reconcileEnclosingRepos` and only then the COBOL tail, which retakes the writer. Decision: keep the gap and document it as benign rather than moving the tail into the closure. Why benign: (1) the closure installs only an untracked repository (it returns early for a tracked prefix or path), so its commit evicts no existing finding and no ledger holds prior rows for the new repository; (2) a settle point reads repository R only when R is in its base, which its own master reconciles inside the same writer section before the read, or when a drained change record names R, which requires either a reconcile that ran after R's commit or the new repository's own per-repository resolver, which is drained only when R is in the base; so a ledger inside the gap reads R in reconciled state, and the tail's later reconcile and ledger append zero rows for unchanged evidence (truth 6 proves the zero-row repeat). Why not move the tail: inside the closure it would run under the new repository's lane and before `reconcileEnclosingRepos`, which must run after that lane is released and which evicts an enclosing repository's copies of the new repository's files; the move reorders those two steps and moves the `deferResolve` handoff to `batchCobolRepos` under the lane, a larger change than the gap warrants. Task 1 has the executor confirm (2) against `recordCobolFindingLedger`'s read set and record the rationale in the SUMMARY; if the read contradicts it, stop and report (deviation rule 4) rather than silently moving the tail.
- Topology batch (blocker of iteration 1): `RunRepositoryTopologyBatch` holds the global writer for its whole callback, so TrackRepoCtx's tail inside a batch with deferResolve false must use the held variant, or it self-deadlocks on the non-reentrant gate (reproduced by `TestNestedTrackedRoot_DeclaredRootsPruneWarmupOrder`, which has no timeout of its own, and `TestNestedTrackedRoot_TrackInsideTopologyBatchCompletes`). Inside a batch the writer is shared by every joined lane, so for those lanes the exclusion reduces to `cobolReconcileMu`; production warmup never ledgers inside the batch (BeginParallelBatch defers every COBOL tail to EndBatch, which runs after the batch returns), so this narrower exclusion applies only to non-deferred batch callers, today the tests (T-05-73).

A writer-held site left on a taking variant deadlocks (caught by the timed suites); a free site on a held variant loses the exclusion (caught by the `TopologyWriterActive` warning and the interleaving test). The executor records the audited call-site table in the SUMMARY.
