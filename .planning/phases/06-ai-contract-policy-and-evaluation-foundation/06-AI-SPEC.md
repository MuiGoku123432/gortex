# AI-SPEC -- Phase 6: AI Contract, Policy, and Evaluation Foundation

> AI design contract generated by `/gsd-ai-integration-phase`. Consumed by `gsd-planner` and `gsd-eval-auditor`.
> Locks framework selection, implementation guidance, and evaluation strategy before planning begins.

---

## 1. System Classification

**System Type:** Structured extraction and bounded review-request preparation

**Description:**
An explicitly authorized Gortex user prepares one reproducible AI review request for one persisted unresolved finding. Direct Go code selects the smallest evidence set from the authoritative scoped graph, records omissions and unavailable artifacts, redacts disallowed content, computes a canonical context digest, checks an explicit provider/model/scope/data-class/retention policy, and only then invokes an existing Gortex LLM provider. Good behavior is fail-closed, metadata-auditable, reproducible from the same graph generation and policy, and unable to change deterministic indexing or graph truth. Phase 6 establishes the request, policy, validation, dataset, and evaluation foundation; persisted AI claims and human review remain Phase 7 work.

**Bounded Context:**
- In scope: policy definition and decision, one-finding context manifest, deterministic evidence selection, redaction, provider dispatch boundary, versioned response-envelope schema, validation foundation, metadata-only audit, evaluation fixtures, and AI-off invariants.
- Out of scope: autonomous agents, arbitrary tool use, vector retrieval, model training, deterministic graph mutation, claim persistence or lifecycle, human-review UI, automatic promotion, and Neo4j synchronization.
- Trust boundary: repository/source and graph content are untrusted data. They cannot alter policy, model, tools, schema, scope, or retention.

**Critical Failure Modes:**
1. Proprietary source or a canary reaches an unauthorized provider, subprocess, log, trace, cache, temporary file, error, or audit record.
2. Provider configuration or connectivity is treated as authorization, including model routing to an unapproved model.
3. Context crosses workspace/project/repository scope, silently expands beyond its finding, or omits relevant unavailable evidence without disclosure.
4. Provider output bypasses closed-schema and semantic evidence/scope validation or mutates deterministic facts.
5. Enabling or disabling AI changes deterministic indexing, reconciliation, persistence, native queries, or the canonical deterministic graph.

## 1b. Domain Context

> Researched from the project parser baseline and handoff, IBM/AWS modernization guidance, CMU SEI legacy-modernization guidance, OWASP LLM02:2025, NIST AI RMF, and current Gortex implementation.

**Industry Vertical:** Mainframe application discovery and COBOL modernization developer tooling

**User Population:** Senior COBOL/mainframe engineers, application discovery analysts, modernization architects, parser/extractor maintainers, security/data-governance owners, and authorized reviewers working with incomplete estates.

**Stakes Level:** High

**Output Consequence:** The request and later claim may influence dependency analysis, parser backlog priority, migration scope, refactor/replatform choices, and human review. A false or leaked result can expose proprietary source, hide a missing dependency, misstate transaction/data impact, or direct unsafe modernization work. It must remain advisory and separate from deterministic truth.

### Known Failure Modes in This Domain

- Treating a bare copybook as a complete COBOL program or assuming unavailable copybook contents.
- Losing fixed-format source coordinates, preprocessing context, program ownership, or multiple source occurrences.
- Resolving dynamic calls, library members, aliases, CTEs, maps, transactions, records, or sets from names alone.
- Confusing a parser recovery tail with absent external source, or using AI to make a deterministic parser regression pass.
- Producing a plausible business-flow narrative while omitting unresolved control-flow boundaries and incomplete-estate lower bounds.
- Recommending broad automated transformation before dependency, functional-equivalence, operational, and business-risk evidence is established.

### Regulatory / Compliance Context

- Proprietary source, credentials, business rules, customer identifiers, and regulated literals require least-privilege access, minimization, explicit provider/retention authorization, and auditable handling.
- OWASP LLM02:2025 calls for sanitization, strict access controls, restricted data sources, transparent retention, and tokenization/redaction; prompts alone are not controls.
- NIST AI RMF Govern/Map/Measure/Manage supports documented ownership, context mapping, measured thresholds, monitoring, and treatment of residual risk.
- Exact organization-specific providers, deployments, regions, training terms, retention periods, encryption requirements, legal hold, and authorization owners remain policy inputs. No provider is approved by this specification.

## 2. Framework Decision

**Selected Framework:** No external AI framework -- direct Go using existing Gortex `internal/llm` provider/service abstractions

**Version:** Gortex repository version for the implementing commit; Go 1.27.x; JSON Schema Draft 2020-12; `github.com/santhosh-tekuri/jsonschema/v6` v6.0.3 if implementation promotes the existing indirect dependency.

**System/Provider Selection:**
- System type is a single bounded structured review operation, not RAG, multi-agent orchestration, or an autonomous agent.
- Reuse `llm.Provider`, `llm.CompletionRequest`, `llm.JSONShape`, provider implementations, token usage, and `llm/svc` lifecycle.
- Add the narrow review request through the existing abstraction rather than using free-form `Service.RunAgent`; the Phase 6 operation needs no arbitrary tools or model-controlled retrieval.
- Provider/model remains a required explicit request and policy input. No concrete hosted, local, CLI, or custom provider is authorized by this document.

**Rationale:**
Gortex already supports local, hosted, CLI/subprocess, and custom providers, structured-output modes, model identity, usage, and clean disablement. Phase 6 is a deterministic policy/context/redaction envelope around one completion, so LangChain, LangGraph, LlamaIndex, CrewAI, or a provider-native agent SDK would duplicate transport, introduce a second configuration and authorization surface, weaken the AI-off invariant, and add non-Go operational dependencies. Direct Go is smaller, auditable, provider-neutral, and required by AI-03 and the milestone's explicit out-of-scope list.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangGraph | Stateful agent orchestration and checkpointing are unnecessary; this operation is linear, deterministic before dispatch, and has no autonomous tools. |
| LlamaIndex | No vector index or model-directed retrieval is permitted; authoritative bounded evidence comes from scoped SQLite graph/source reads. |
| LangChain | Adds Python/TypeScript abstraction and provider duplication to a simple Go completion boundary. |
| OpenAI/Anthropic agent SDKs | Vendor lock-in conflicts with the existing provider-neutral abstraction and explicit provider policy. |
| Promptfoo/Phoenix as runtime dependencies | Useful only if later evidence justifies external experiment/tracing infrastructure; Phase 6 can evaluate deterministically in Go without exporting protected payloads. |

**Vendor Lock-In Accepted:** No. Policy may authorize a named provider/model per request, but the product contract remains provider-neutral.

### Entry Point Pattern
```go
func PrepareAndDispatchReview(ctx context.Context, req ReviewRequest) (ReviewResult, error) {
    decision, err := policy.Authorize(req.Authorization) // before source retrieval/serialization
    if err != nil || !decision.Allowed {
        return ReviewResult{}, ErrPolicyDenied
    }

    manifest, payload, err := contextBuilder.Build(ctx, decision.Scope, req.FindingID)
    if err != nil {
        return ReviewResult{}, err
    }
    payload, redactions, err := redactor.Apply(payload, decision.DataClass)
    if err != nil {
        return ReviewResult{}, err
    }
    manifest.Redactions = redactions
    manifest.Digest = sha256.Sum256(canonicalBytes(manifest, payload))

    raw, err := provider.Complete(ctx, llm.CompletionRequest{
        Messages: buildReviewMessages(manifest, payload),
        MaxTokens: decision.MaxOutputTokens,
        Shape:     llm.ShapeReviewEnvelope,
    })
    if err != nil {
        return ReviewResult{}, err
    }
    return validateReviewEnvelope(raw.Text, manifest, decision.Scope)
}
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---------|------------|-----------------|
| `llm.Provider` | Existing provider-neutral completion transport | Only after policy, scope, context, redaction, and manifest gates pass. |
| Authorization policy | Versioned allow-list keyed by provider, exact model/deployment, endpoint/region where applicable, scope, data class, and retention mode | Every review request; configuration never substitutes for it. |
| Context manifest | Canonically ordered metadata naming finding, active graph generation, evidence IDs/ranges, omissions, unavailable artifacts, redactions, budgets, versions, and digest | Before dispatch, audit, replay comparison, and validation. |
| Closed output schema | Draft 2020-12 response-envelope contract with required fields, bounds, enums, and `additionalProperties: false` | Provider structured output and deterministic post-response validation. |
| Semantic validator | Go checks that every evidence ID/range is active and in the authorized manifest/scope | After schema validation and before any Phase 7 persistence. |
| Metadata-only audit | Owner-restricted record of decision and execution metadata without raw prompt/context/response | Allowed, denied, failed, and validated attempts. |

### Common Pitfalls
1. `Config.IsEnabled()` and successful `provider.New` only prove technical capability; neither authorizes source transmission.
2. Provider-native strict structured output is not validation. Always parse and validate locally, then validate evidence IDs, ranges, active generation, and scope.
3. Do not route this operation through `Service.RunAgent`: it creates graph tools, may route models, and can record raw framed prompts/responses.
4. Current conversation logging writes raw requests/responses to `0644` JSONL when enabled; protected review payloads must bypass it unless a future explicit raw-retention policy redesigns the sink.
5. Canonicalize ordering and serialization before hashing; never digest Go map iteration order or provider-formatted prompts.

## 4. Implementation Guidance

**Model Configuration:**
- AI remains disabled by default. No policy entry means deny even when a provider is configured.
- Request must name an exact provider and model/deployment. Disable automatic model routing for this operation unless the routed provider/model is itself explicitly authorized and recorded.
- Prefer temperature `0` where supported, bounded output tokens, no streaming, and provider-native strict schema mode when available. Provider-native controls are advisory; local validation is mandatory.
- Local, CLI/subprocess, custom, and hosted providers all cross policy boundaries. “Local” describes transport, not authorization.

**Authorization Separate From Configuration:**
- Configuration constructs a provider and stores endpoint/model capability. A separate versioned policy authorizes exact provider/model/deployment, endpoint/region where applicable, workspace/project/repository allow-set, data class, retention mode, context/output budgets, and expiry.
- Evaluate authorization before reading source bytes, assembling payloads, spawning subprocesses, or opening provider connections.
- Missing, ambiguous, stale, broader-global-over-narrow-local, or routing-expanded policy fails closed. Allowed and denied attempts receive a metadata-only request ID and policy decision.

**Core Pattern:**
1. Resolve explicit principal, finding ID, active graph generation, requested provider/model, scope, data class, and retention mode.
2. Authorize those exact values without retrieving protected source.
3. Build a deterministic allow-set and bounded manifest from the selected finding; reject missing/ambiguous scope and unhealthy ownership.
4. Select only required source ranges and graph evidence. Declare unavailable artifacts, omitted evidence, truncation, and lower-bound implications.
5. Redact secrets, credentials, protected literals, identifiers/classes prohibited by policy, and disallowed paths before any provider/log serialization.
6. Canonically sort records, serialize a versioned envelope, and compute digest over manifest plus redacted payload.
7. Dispatch through the existing provider with a closed structured-output shape and no tools.
8. Strictly decode, validate JSON Schema, then verify evidence/scope semantics. Phase 6 returns an experimental result only; Phase 7 owns claim persistence.
9. Audit metadata only: request/decision ID, provider/model, policy/schema/context-builder/redactor versions, scope IDs, manifest/context digest, redaction counts/classes, omissions count, usage, timing, status, and normalized error class.

**Tool Use:** None. The model receives delimited evidence records and emits one response envelope. It cannot retrieve files, invoke Gortex tools, execute commands, alter policy, or write graph state.

**State Management:** SQLite remains authoritative for deterministic findings/evidence. Phase 6 may persist only policy and metadata-audit state required by the plan. Raw prompt, source payload, and response are not persisted by default. Confidential audit artifacts use owner-only permissions (`0700` directory, `0600` files), bounded policy retention, explicit deletion/rotation, and observable write health. An audit-path failure blocks dispatch when policy requires the audit record.

**Context Window Strategy:** Start from one finding and a fixed evidence recipe: exact range, containing program/division/section/paragraph, nearby deterministic nodes, directly relevant declarations/value flow, available dependencies, parser diagnostics, and unavailable/omitted list. Apply deterministic per-class byte/item budgets and stable truncation order. Reject over-budget context instead of silently widening or allowing the model to retrieve more.

**AI-Off Invariants:**
- No provider construction or invocation, subprocess spawn, network request, context source read, AI audit write, or AI schema evaluation occurs when AI review is disabled.
- Deterministic indexing, reconciliation, SQLite commits, findings, native CLI/MCP queries, and exports continue normally with no provider credentials or binaries.
- Canonical active deterministic graph snapshots are byte/identity equivalent between AI-on and AI-off runs for identical deterministic inputs.
- Provider, policy, audit, redaction, or validation failure cannot mutate deterministic facts or close unresolved findings.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic-Equivalent Go Validation

The stock template requests a Pydantic example, but Gortex is Go and adding Python would create an unjustified second runtime. The direct Go equivalent below is the normative implementation pattern: a typed envelope plus a closed Draft 2020-12 JSON Schema compiled with `jsonschema/v6`. Decode with unknown-field rejection, cap input size, validate schema, then run graph-aware semantic checks. One bounded retry may be allowed only for schema-invalid output, using the same authorized redacted context; policy/scope/redaction failures never retry. Pydantic is explicitly not selected or required.

```go
type ReviewEnvelopeV1 struct {
    SchemaVersion  string         `json:"schema_version"`
    FindingID     string         `json:"finding_id"`
    Classification string        `json:"classification"`
    Confidence    float64        `json:"confidence"`
    Rationale     string         `json:"rationale"`
    Evidence      []EvidenceRef  `json:"evidence"`
    MissingContext []string      `json:"missing_context"`
}

func validateReviewEnvelope(raw []byte, schema *jsonschema.Schema) (ReviewEnvelopeV1, error) {
    var value any
    if err := json.Unmarshal(raw, &value); err != nil {
        return ReviewEnvelopeV1{}, err
    }
    if err := schema.Validate(value); err != nil {
        return ReviewEnvelopeV1{}, err
    }
    var out ReviewEnvelopeV1
    dec := json.NewDecoder(bytes.NewReader(raw))
    dec.DisallowUnknownFields()
    if err := dec.Decode(&out); err != nil {
        return ReviewEnvelopeV1{}, err
    }
    return out, validateEvidenceAgainstManifest(out)
}
```

Schema requirements include fixed `schema_version`, bounded arrays and strings, confidence in `[0,1]`, enumerated classifications, required `missing_context`, unique evidence references, and `additionalProperties: false` at every object level. Semantic validation rejects unknown, inactive, stale, out-of-manifest, or cross-scope evidence.

### Async-First Design

Use synchronous request semantics over context-aware Go APIs; provider implementations already perform blocking I/O behind `context.Context`. Do not add queues, streaming, or goroutine fan-out in Phase 6. Cancellation/deadlines must stop dispatch and preserve a metadata-only terminal status. Never detach work from the request context when that could outlive authorization or retention scope.

### Prompt Engineering Discipline

- Fixed versioned system instructions define task, schema, evidence delimiters, and explicit prohibitions; source and graph text are labeled untrusted data.
- User content contains the canonical manifest and redacted evidence only. It cannot select provider, change policy, enable tools, or alter the schema.
- Prefer a small set of labeled COBOL examples from the reference dataset. Keep examples synthetic or approved and version them with the prompt.
- Require explicit `missing_context`; direct the model to abstain when evidence is insufficient. Never ask for hidden chain-of-thought.

### Context Window Management

No embeddings or RAG index. Use deterministic graph adjacency and source ranges from SQLite, stable evidence ordering, class-specific budgets, and explicit truncation/omission records. Context construction is independently testable without a provider. The digest binds manifest version, active graph generation, selected evidence identifiers and revisions, redaction metadata, and exact redacted payload bytes.

### Cost and Latency Budget

- Policy supplies maximum input bytes/tokens, output tokens, requests per finding, and timeout; requests over budget fail before dispatch.
- Record provider-reported or estimated token usage and latency without content. Do not implement cross-request prompt caching for proprietary payloads unless retention policy explicitly authorizes it.
- No model routing by default. A lower-cost model is usable only when explicitly named, authorized, and separately evaluated against the same reference set.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric | Measurement Approach | Priority |
|-----------|--------|----------------------|----------|
| Authorization isolation | Pass only if every allowed request exactly matches provider, model/deployment, endpoint/region where applicable, scope, data class, retention mode, and unexpired policy; every denied case emits zero provider bytes/processes. | Code + outbound/subprocess spy | Critical |
| Redaction and sink safety | Pass only if seeded secrets/protected markers are absent from outbound request when disallowed and absent from logs, audits, traces, errors, caches, temp files, rotations, and returned validation errors. | Code canary scan + security review | Critical |
| Context determinism | Pass only if repeated builds over the same finding/generation/policy produce identical ordered manifests and digests; changed evidence/version/policy changes the digest. | Golden/property tests | Critical |
| Scope correctness | 5: only authorized evidence; 3: harmless omission disclosed; 1: cross-scope inclusion, ambiguous selection, or undisclosed widening. Any score 1 blocks. | Code + human review | Critical |
| Manifest completeness | Pass only if unavailable artifacts, relevant omissions/truncation, redaction classes/counts, budgets, source revisions, and builder/schema versions are declared. | Code + domain expert | Critical |
| Schema validity | Pass only for strict versioned schema, no unknown fields, all bounds/enums satisfied, and unique evidence references. Target 100%. | Code validator/fuzz | Critical |
| Evidence citation validity | Pass only when every citation exists, is active, is in the manifest and authorized scope, and matches an exact graph ID or range. Target 100%. | Code validator | Critical |
| Unsupported-claim rate | A material classification/rationale assertion not supported by supplied evidence is a failure. Experimental threshold <= 5%; release threshold <= 2%, with zero fabricated artifact contents. | Human rubric; calibrated LLM judge only as secondary | Critical |
| COBOL semantic quality | 5: distinctions and uncertainty preserved; 3: useful but misses a disclosed nuance; 1: false resolution/behavior. Mean >= 4.0 and no critical score 1. | Two domain reviewers | High |
| Abstention/missing-context quality | Pass when insufficient evidence leads to explicit abstention or bounded hypothesis plus the exact artifact needed to verify it. Target >= 95% on insufficient-context cases. | Human + code fields | High |
| AI-off equivalence | Canonical deterministic nodes, edges, findings, provenance, and query outcomes are identical with AI enabled versus disabled. Target 100%. | Snapshot/integration tests | Critical |
| Audit durability and privacy | Required metadata is written with `0600` files/`0700` directory, retention and rotation are bounded, failures are observable, and no raw payload appears. Target 100%. | Filesystem/failure injection | Critical |
| Latency and budget | No request exceeds policy input/output/request/timeout limits; report p50/p95 by provider/model without source. | Code metrics | Medium |

### Quality Gates and Thresholds

- Gate A -- security: 100% policy-denial isolation, scope isolation, redaction canary containment, and sink scans. Any leak or unauthorized byte/process is release-blocking.
- Gate B -- deterministic contract: 100% manifest reproducibility, schema validity, citation validity, AI-off graph equivalence, and no deterministic mutation.
- Gate C -- domain utility: unsupported-claim rate <= 5% for experimental use, <= 2% before wider release; COBOL semantic mean >= 4.0/5; insufficient-context abstention >= 95%; zero fabricated missing-artifact contents.
- Gate D -- audit operations: 100% required metadata records or fail-closed dispatch, owner-only permissions, tested retention/deletion, and observable disk/handle failures.
- Model/provider approval is per exact model/deployment and reference-set result. Passing one model does not approve another or a routing tier.

### Eval Tooling

**Primary Tool:** Native Go table/golden/property/fuzz/integration tests with deterministic validators and outbound-provider spies.

**Override From Arize Phoenix Default:** Phoenix is not selected for Phase 6. External tracing creates a new source/retention boundary, and current needs are metadata counters plus reproducible offline fixtures. Reconsider OpenTelemetry-compatible or Phoenix tracing only after a policy-approved metadata-only export proves operational need; never export raw prompts/context/responses by default.

### Reference Dataset

**Size:** 20 initial labeled cases, expanded only from observed failure families.

**Composition:**
- 4 clean bounded `PARSE_UNRESOLVED` cases: COBOL structure, DATA DIVISION, SQL, and CICS/IDMS.
- 3 `EXTERNAL_UNRESOLVED` cases: missing copybook, called program, and metadata/schema artifact, each requiring abstention from invented contents.
- 3 scope cases: duplicate names across repository/project/workspace, ambiguous scope, and explicitly authorized cross-repository evidence.
- 3 security cases: credential/protected literal, prompt injection in comment/identifier, and provider/log/temp-file canaries.
- 3 context cases: omitted relevant declaration, over-budget context, and deterministic truncation/unavailable-artifact declaration.
- 2 malformed-output cases: unknown/oversized fields and out-of-scope/stale evidence IDs.
- 2 lifecycle/AI-off cases: identical replay and changed source/parser/context-builder/policy version.

Each case stores synthetic or explicitly approved source, deterministic finding and graph fixture, authorization policy, expected manifest/evidence set/digest relation, redaction expectations, allowed/denied dispatch, valid response examples, semantic labels, and prohibited outcomes. Raw production source is not copied into the dataset by default.

**Labeling:** Two reviewers for semantic cases: one senior COBOL/mainframe engineer and one Gortex/parser maintainer. Security cases require data-governance sign-off. Disagreements are adjudicated and rubric changes version the labels. An LLM judge may assist only after >= 0.7 correlation with human scores on a held-out labeled subset and never decides security, scope, schema, citation, or release gates.

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| AI disabled | Feature/policy disabled or no explicit request | Do not construct/invoke provider; return deterministic result path unchanged. |
| Authorization denial | Missing/mismatched provider, model, endpoint/region, scope, data class, retention, expiry, or principal | Block before source retrieval, serialization, network, or subprocess spawn; audit metadata only. |
| Scope/ownership failure | Missing/ambiguous scope, cross-scope evidence, or nonzero unowned/misprefixed records in selected scope | Block and report normalized scope-health reason without source. |
| Context budget/completeness failure | Required evidence cannot fit, canonical selection fails, or omissions/unavailable artifacts are not declared | Block; never silently widen or truncate outside the deterministic policy. |
| Redaction failure | Secret/protected class detected but cannot be safely transformed, or canary survives | Block; emit counts/classes only. |
| Audit-path failure | Policy requires durable audit and owner-restricted write/rotation fails | Block dispatch; surface audit health without payload. |
| Provider/model drift | Runtime provider/model differs from authorized exact value, including routing | Block dispatch. |
| Schema failure | Invalid JSON, unknown fields, type/enum/bound violation | Reject; permit at most one same-context repair retry if policy allows. |
| Semantic evidence failure | Unknown, stale, inactive, omitted, or cross-scope evidence; attempted deterministic mutation | Reject with metadata-only reason; no persistence or graph mutation. |
| Prompt injection | Source/graph text asks to alter instructions, tools, provider, scope, or output contract | Treat as data; model has no tools; external guards remain authoritative. |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| Unsupported-claim and abstention rates | All reference cases plus 100% of rejected/contradicted future reviews | Block model/prompt promotion; inspect rubric and evidence recipe. |
| Manifest/citation failures | Every invocation metadata record | Release block for any deterministic contract failure. |
| Redaction and scope canaries | Every CI/security run and periodic policy-owner test | Disable affected provider/policy and investigate sinks. |
| Recurring gap family impact | Aggregate metadata by normalized gap family, frequency, inbound references, and affected programs | Prioritize deterministic parser/extractor improvement; AI does not become permanent parser replacement. |
| Provider/model quality drift | Stratified sample by exact provider/model, gap family, low confidence, retry, and unusual token/latency | Re-run reference set and suspend model authorization if thresholds fail. |
| Human outcome distribution | All future Phase 7 confirm/contradict/reject/supersede events, metadata only | Recalibrate rubric/model; investigate families with high contradiction/rejection. |

## 7. Production Monitoring

**Tracing Tool:** Existing Gortex metrics/logging conventions with a dedicated metadata-only AI audit/telemetry path. No raw OpenTelemetry/Phoenix GenAI prompt or completion events. A future OTel/Phoenix integration must be policy-reviewed and restricted to the fields below.

**Permitted Metadata:** Request/decision ID, timestamp, principal/authorization reference, exact provider/model/deployment, policy/schema/context-builder/redactor versions, workspace/project/repository IDs, finding ID or keyed digest where policy requires, active graph generation, manifest/context digest, data class, retention mode, redaction classes/counts, evidence/omission/unavailable counts, token usage, latency, status, normalized denial/failure class, retry count, and audit health. Never raw source, prompt, context, response, rationale, secret value, or model error body by default.

**Key Metrics to Track:**
- Requests allowed/denied by policy version, provider/model, scope, data class, retention mode, and normalized reason.
- Context-build, redaction, schema, semantic-citation, provider, and audit-path failures.
- Manifest evidence/omission/unavailable counts, redaction counts, input/output tokens, latency, retries, and budget rejections.
- Reference-set schema validity, citation validity, unsupported-claim, abstention, and COBOL semantic scores by exact model/prompt/context-builder version.
- AI-on/off deterministic snapshot mismatches and any attempted deterministic mutation.

**Alert Thresholds:**
- Page/block immediately: any unauthorized outbound byte/process, source/canary in a prohibited sink, cross-scope evidence, deterministic mutation, AI-on/off mismatch, schema/citation acceptance below 100%, or required audit failure.
- Disable exact model/policy pending review: unsupported-claim rate > 5% experimental or > 2% release, abstention < 95%, COBOL semantic mean < 4.0, or any fabricated missing-artifact content.
- Investigate: p95 latency/usage exceeds policy budget, provider failures > 5% over 15 minutes with at least 20 attempts, or denial/redaction failure rate doubles against baseline.

**Smart Sampling Strategy:**
Review all security/scope/schema/citation failures and future contradicted/rejected claims. Stratify successful requests by provider/model, gap family, data class, repository, redaction count, missing-context count, low confidence, retry, high token use, and high latency. Sample only metadata by default; access to approved raw artifacts requires a separate policy, owner, retention period, and audit trail.
